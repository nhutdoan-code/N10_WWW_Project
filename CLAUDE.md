# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

PhoneNest is a phone/accessory e-commerce site (university group project). Domain names, entities, DB tables and many comments are in Vietnamese (e.g. `SanPham` = product, `PhienBanSanPham` = product variant, `DonHang` = order, `GioHang` = cart, `KhachHang` = customer, `NhatKyHoatDong` = audit log, `HanhViNguoiDung` = user behavior event). Keep new code consistent with these names.

## Layout

- `BE/phonenest/` — Spring Boot 3.5 backend (Java 21, Maven, Lombok, Spring Data JPA, Spring Security + JWT, Spring AI 1.1). Package root `nhom10.phonenest`.
- `FE/` — React 19 + Vite SPA (axios, react-router-dom 7).
- `DB/` — MariaDB SQL: `schema/`, `seed/`, numbered `migrations/` (many with `_rollback.sql` pairs), and `phonenest_full.sql` (consolidated schema + migrations + seeds). See `DB/README.md`.
- `API_DOCUMENTATION.md` — REST API reference.

## Commands

Backend (no Maven wrapper in the repo; use a local/IDE-bundled `mvn`, run from `BE/phonenest`):
```bash
mvn spring-boot:run                       # API on :8080
mvn test                                  # all tests
mvn test -Dtest=CheckoutIdempotencyServiceTest            # one class
mvn test -Dtest=CheckoutIdempotencyServiceTest#methodName # one method
```

Frontend (from `FE/`):
```bash
npm install
npm run dev      # Vite on :5173, proxies /api and /uploads to :8080
npm run build
npm test         # node --test tests/*.test.js
```

Database: import into an **empty** `BanDienThoai` DB (utf8mb4). `phonenest_full.sql` deliberately fails if the target already has tables and uses strict `CREATE TABLE` — don't add `IF NOT EXISTS`, `DROP DATABASE`, `USE`, `INSERT IGNORE` or `REPLACE INTO`. Hibernate runs with `ddl-auto=none`, so every schema change needs a new numbered migration in `DB/migrations/` (plus a rollback script, following current practice) and a matching JPA entity update.

## Backend architecture

- Layering: `controller` → `service` → `repository` (Spring Data JPA), with `dto` + `mapper` for API shapes and `entity` mirroring the hand-written SQL schema. `PhysicalNamingStrategyStandardImpl` is used, so entity field names map verbatim to camelCase column names (`maSanPham`, `soLuongTon`, ...).
- IDs are strings generated by `util/IdGenerator.next(prefix)` (prefix + millis + 3-digit seq), not DB auto-increment.
- Errors: throw `exception/AppException` (status + message, optional `code`); `GlobalExceptionHandler` renders `{"message", "code"?}` JSON. The FE reads `message` from error responses.
- Security (`security/config/SecurityConfig`, `JwtFilter`, `util/JwtUtil`, `util/SecurityUtil`): stateless JWT. Route prefixes encode roles — `/api/admin/**` → `ADMIN`, `/api/customer/**` and `/api/notifications/**` → `CUSTOMER`; `/api/auth/**`, tracking POSTs, MoMo IPN, `/api/chat`, and selected catalog GETs are public. New endpoints must be placed under the right prefix / matcher.
- Audit: admin mutations call `NhatKyHoatDongService.ghi(...)` inside the same transaction as the business change (rollback together); `AuditDiffUtil` computes before/after diffs.
- `aspect/LoggingAspect` logs timing for every `service..*` method.
- Inventory/checkout concurrency is a recurring concern: checkout idempotency (`CheckoutIdempotencyService` + `CheckoutIdempotencyTxHelper`), voucher usage limits, and stock movements (`BienDongKho`) each have dedicated migrations and concurrency tests — preserve their locking/transaction semantics when touching `DonHangService`, `GioHangService`, `KhoService`, `KhuyenMaiService`.
- Sales approval (`enums/TrangThaiPheDuyet`, migrations 15+16) on `PhienBanSanPham` is independent of business status and stock. `PheDuyetBanHangPolicy.duocPhepBan` = business status OK + `APPROVED` + approval fingerprint matches current price/list price/RAM/ROM/colour; enforced in cart, order and payment services. State changes go through `PheDuyetBanHangService` (row lock + admin-confirmed data, unblock only to `PENDING_REVIEW`). Admin edits carry concurrency tokens (`maKiemTraSua`, `maKiemTra`) and get 409 when stale; DB lock conflicts also map to 409. Public APIs/chatbot/vector store expose only *published* prices (`PheDuyetBanHangPolicy.giaCongBo`); unapproved variants have no `giaBan` in public JSON. Stock changes only via `KhoService` (ledger `BienDongKho`); the product form ignores stock of existing variants.
- Persistence: Hikari uses READ COMMITTED; `findByIdForUpdate` on variants/orders/vouchers lives in `repository/Khoa*Repository` fragments that lock **and refresh** the entity (plain `@Lock` queries return stale already-loaded entities). `config/schema/SchemaCompatibilityVerifier` fails startup if the DB lacks M15/M16 or `pn_migration_log` is inconsistent.
- Payments: MoMo test gateway (`MomoPaymentService`, `PaymentController`), configured via `MOMO_*` env vars. IPN must be a public HTTPS URL; signature and amount are verified against the order before recording payment.

### AI
- Chat: Spring AI `ChatClient` backed by Google Gemini (`spring.ai.model.chat=google-genai`, `gemini-3.8-flash`, override with `GEMINI_MODEL`) in `ChatService`, personalized with `UserPreferenceAggregationService` (built from `HanhViNguoiDung` tracking events) and product recommendations. Chat history is isolated per user.
- Embeddings / semantic search: `service/ai/` — custom `PhoneNestEmbeddingModel` calls local Ollama `bge-m3` (1024 dims, `phonenest.ai.embedding.*` properties), `PhoneNestVectorStore` is an in-app vector store indexed at startup from `ProductSemanticDocumentBuilder`. If Ollama is down, `SemanticSearchService` falls back to keyword search instead of failing.

## Frontend architecture

- `src/config/api.js`: single axios instance (`baseURL: /api`) that attaches the JWT from local storage and unwraps `res.data`; a 401 clears the user and redirects to `/login`. Service modules in `src/service/` wrap it per domain.
- Global state via React contexts in `src/context/` (Auth, Cart, Compare, Toast) exposed through hooks in `src/hooks/`.
- Routing in `src/routes/AppRoutes.jsx` with `ProtectedRoute`; customer pages use `MainLayout`, admin pages (`src/pages/admin/`) use `AdminLayout`.
- `ActivityTracker` + `trackingService` send behavior events to `/api/tracking/**`, which feed AI personalization.

## Tests

- Most backend tests are Mockito unit tests (no DB needed).
- `@SpringBootTest` integration tests (`ApprovalWorkflowIntegrationTest`, `ApprovalConcurrencyIntegrationTest`, `SalesApprovalIntegrationTest`, `UserBehaviorTrackingRealIntegrationTest`) run only when `PHONENEST_IT_DB_URL` is set, and `support/ItDatabaseGuard` refuses any DB not named `phonenest_it_*` / `claude_2b7x_*` on localhost. Create a disposable clone with `DB/tests/create_it_clone.sh`. Never point tests at the main `bandienthoai` database.
- Migration scripts 15/16 have their own clone-based suite: `DB/tests/test_migrations_15_16.sh`.
- Browser E2E: `FE/e2e/` (Playwright, system Chrome) against an E2E clone — see `FE/e2e/README.md` and `docs/HUONG_DAN_CAU_HINH_LOCAL.md`.

## Configuration

`application.properties` reads secrets from env vars (`GEMINI`/Spring AI key, `SPRING_MAIL_*`, `MOMO_*`, JWT, `OLLAMA_BASE_URL`, `OLLAMA_MODEL`, `TRACKING_RETENTION_DAYS`). Default dev DB is `jdbc:mariadb://localhost:3306/BanDienThoai` (DB README examples use port 3307). Uploaded images are served from `app.upload-dir=uploads` at `/uploads/**`.
